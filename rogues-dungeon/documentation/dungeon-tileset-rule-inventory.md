# Dungeon tileset rule inventory

This inventory is the implementation baseline for `unify-dungeon-tileset-wang-rules`.

## Authoritative asset contract

- TSX source: `rogues-dungeon/public/assets/art/vendors/dungeons-and-pixels-v1.4/tiled-examples/tilesets/tileset-dungeon.tsx`
- Declared image: `../../tilesets/tileset-dungeon.png`
- Resolved image: `rogues-dungeon/public/assets/art/vendors/dungeons-and-pixels-v1.4/tilesets/tileset-dungeon.png`
- Atlas: 384 × 288 pixels, 12 columns × 9 rows, 32 × 32 tiles, 108 local IDs.
- Wang order: `N, NE, E, SE, S, SW, W, NW`; bit weights are `1, 2, 4, 8, 16, 32, 64, 128`.

The TSX is the authored source. Runtime TypeScript may consume only a validated derived representation; it must not become a second authoring table.

## Existing authored Wang families

The TSX currently contains `Room frame`, `Void frame`, and `Details`. The implementation will retain these families and add an explicit generated-wall boundary family for blocked-cell neighbor masks, because the reported tile-5/tile-17 mapping is defined from the blocked cell's walkable-neighbor mask rather than the walkable cell's own room-frame mask.

## Generator topology inventory

- Rectangular start room and generated rooms.
- Room-to-room sockets at least one tile from corners.
- One-, two-, and three-wide horizontal/vertical corridors.
- Corridor bends, T joins, plus joins, and room openings.
- Layered corridor scenario used by `corridor-joins`.
- Start-room wall/decorative boundary.
- Deep unreachable void and void-frame boundaries.
- Detail overlays that must remain separate from structural wall roles.

The complete observed mask set is generated by the validator rather than maintained by hand. A new generator output is a validation failure until it receives an exact TSX rule or is intentionally constrained.
